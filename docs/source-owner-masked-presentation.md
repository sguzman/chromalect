# Presentation-masked source-owner rehearsal (v0.1)

The [rehearsal gallery](../site/source-owner-masked-preview.html) is a **read-only, non-collecting engineering preview** of both source-derived component region masks for the 49 color-warning pairs across 48 first-tranche Mandarin glyphs. The build derives its own versioned 49-record stimulus manifest and 98 neutral SVGs from the same original source, five-fold warning, v0.6 palette, and independently unapproved complementary locator manifests as the source-owner evidence intake. The browser fetches only this key-reduced manifest and its selected neutral SVG images; it does not load the original owner-key manifest or palette.

The viewer presents a font-dependent native character and two equally sized **charcoal-on-gray region masks**, labeled Region A and Region B. It does not display the machine owner-answer label or experimental source colors in its page text. Presentation sides follow the source candidate A/B order; the originally selected target locator appears on opposite sides in 25 versus 24 records. This is **not random assignment** or a scientifically blinded stimulus procedure; component forms and source path locators remain provisional.

The browser verifies SHA-256 of **both downloaded neutral SVG files** against the pinned key-reduced manifest before displaying either one. When supported, AbortController cancels superseded downloads during rapid selection changes; stale operations are also guarded by a monotonically increasing selection version so late results can never replace the current display. It reuses only already-verified SVG bytes from a bounded, page-lifetime-only least-recently-used cache (24 masks, maximum 24 MiB given the per-mask size limit). Unverified downloads are never cached, evicted masks are reverified when next fetched, and the cache does not use persistent browser storage. It constructs temporary, read-only object URLs from verified bytes, revokes the prior pair on navigation, and discards stale asynchronous results. Missing Web Crypto, inaccessible images, oversized images, or a checksum mismatch leave both masks blank and visibly report failure rather than showing unverified geometry. Verification establishes **byte identity with the generated source**, not correctness of component ownership.\n\nThe page supports 16, 24, 32, 48, 64, 96, 128 and 160 CSS pixel comparisons; all 49 pairs or the exact 23 introduced, 21 resolved and five retained warning-cohort subsets; and link fragments selecting a known public pair ID. Previous/next controls follow canonical source order **within the selected cohort** and stop at the first/last pair. Changing the cohort resets the sequence when the current pair is outside the new subset, while preserving a valid current selection. The neutral masks preserve original source SVG path geometry and fill colors **while intentionally stripping the `data-component` owner attributes**. Machine checks verify source derivation, source SHA-256 references, unchanged path coordinates, and disjoint highlighted regions; this establishes reproducible geometry, not independently correct owner interpretations.

## Blinding and eligibility boundary

This view is **not** an independently blinded expert-review instrument. The masked preview manifest contains no machine-selected owner-key fields, and its generated SVG paths omit all `data-component` attributes. The publicly hosted original source manifests and machine-key-visible evidence intake remain accessible separately, so navigating to those files or examining the source history can still reveal the original mapping. The native-font rendering is locally variable. The source's paired component masks are mutually derived from the same mapping, so they do not provide independent corroboration.

The rehearsal intentionally has **no assessment response controls, reviewer identifiers, evidence-note export, browser persistence, or network submission actions**. No human trials are represented by its automated tests. The [independent protocol](source-owner-independent-adjudication-protocol.md) continues to record zero independent reviewers, accepted mappings and study eligibility. A future actual reviewer-blind procedure must separately freeze preregistration, remove machine-owner metadata from reviewer-facing materials and enforce reviewer isolation with provenance/independence checks before outcomes can be called independent.

## Reproducible checks

The publication pipeline regenerates original and complementary SVGs from pinned source glyphs, verifies their SHA-256 identities and byte-exact geometry, publishes key-reduced SVGs and a separate manifest, and then checks their derivation and the viewer:

    node tools/glyph-pipeline/source_owner_masked_stimuli.mjs --write
    node tools/glyph-pipeline/source_owner_masked_stimuli.mjs --check
    node tools/glyph-pipeline/source_owner_masked_stimuli_smoke.mjs
    node tools/glyph-pipeline/source_owner_masked_preview_viewer_smoke.mjs

These checks test rendering inputs, pair/size navigation, negative cases and absence of collection behavior. They cannot establish reviewer independence, legibility, or source-owner correctness.
